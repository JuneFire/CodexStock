# 功能说明

本文件记录 README 未覆盖的新增功能：竞价封单额抓取、早盘预案、预案网页、历史页降级、竞价数量缩减、昨连板标注、情绪周期环境标签。

## 1. 竞价封单额 Top20 抓取

交易日集合竞价期间（9:15 / 9:20 / 9:25 三个时点），全市场扫描每只股票的**封单额**（= 买一量(手) × 100 × 买一价），按封单额降序取前 20 存入 MySQL `auction_seal` 表。

### 数据来源

腾讯批量直连 `qt.gtimg.cn`（唯一可行路径）：

- 新浪全市场接口只有买卖**价**无买一量 → 无法算封单
- 东方财富直连在本机被连接层拦截 → 排除
- 封单额 = 买一量(手) × 100 × 买一价（元）；竞价阶段封单股买一即涨停价、买一量即涨停委托量

### 表结构 `auction_seal`

每行 = 日期 + 代码 + 时点 + 买一/卖一档位 + 封单额。唯一键 `(trade_date, code, sample_time)`，upsert 覆盖（同一时点重跑不产生重复行）。

| 字段 | 含义 |
|---|---|
| `sample_time` | 抓取时点：09:15 / 09:20 / 09:25 |
| `bid1_price` / `bid1_volume` | 买一价 / 买一量（手） |
| `ask1_price` / `ask1_volume` | 卖一价 / 卖一量（手） |
| `seal_amount` | 封单额（元）= 买一量(手)×100×买一价 |
| `seal_rank` | 当日该时点封单额排名 |

### 接口

- `GET /api/seal?date=YYYY-MM-DD`：某日封单数据（按时点、封单额降序）
- `GET /api/seal/dates`：有封单数据的日期列表

## 2. 早盘预案自动生成

每个交易日 **8:30** 自动生成当天早盘预案文本（复盘 + 次日预案），写入 `data/plan/<日期>.txt`。

### 数据来源

基于**昨日**收盘复盘数据（指数/情绪/涨停池/连板梯队/封单/头马黑马）+ 隔夜消息（WebSearch），按 `.claude/skills/daily-plan/SKILL.md` 的方法论生成。

### 预案结构

```
<日期>早盘预案
大局观        （指数关键位/情绪/风标/题材/消息）
具体机会解析  （短线个股判断 + 题材分块）
总结          （周期判断/风格/节奏）
```

### 生成方式

两种方式并存：

1. **后端自动**：`plan_fetch_loop` 守护线程，交易日 8:30 触发（server.py `_run_plan_generation`），基于最近已保存复盘生成基础预案。
2. **Claude 定时任务**（增强版）：Claude Code scheduled task `daily-plan-morning`，交易日 8:30 触发，调用 `daily-plan` skill 用 LLM 深度推演（个股买卖判断/隔夜消息/产业链标的），生成后写 txt + 填充复盘 manual 字段。此方式质量更高，需 Claude 环境。

### 关键规则

- **只补空缺，不覆盖**：读回已有 manual 后只填空字段，保留用户手写内容（`POST /api/review` 是整体替换，须先读后合并再全量 POST）
- 预案基于昨日数据，manual 填到今日 review 记录
- 9:10 前今日竞价数据尚不存在，严禁写成今日实况

## 3. 预案网页

浏览器查看早盘预案的页面。

- 地址：`http://<服务器IP>:8010/plan.html`（各页顶栏"预案"按钮进入）
- 默认显示最新一份预案，带日期切换（上一页/下一页翻看历史）
- 预案按 大局观/具体机会解析/总结 三大节渲染，股票名/连板数/大盘点位/涨跌/关键位高亮着色（红涨绿跌、连板青色、关键位橙色）

### 接口

- `GET /api/plan?date=YYYY-MM-DD`：读取某日预案文本
- `GET /api/plan/dates`：已有预案的日期列表

## 4. 历史页 JSON 降级

MySQL 不可用时，历史页自动降级读取 `data/history/*.json` 归档，无需改动前端。

### 触发条件

任一历史接口调 `db.*` 抛异常时自动降级（懒连接失败即触发），响应带 `fallback: true`。

| 接口 | 降级行为 |
|---|---|
| `/api/history/dates` | 读 `data/history/*.json` 列表，分页正常 |
| `/api/history/date` | 读单日 JSON 快照（格式与 `get_day` 一致） |
| `/api/history/stock` | 跨 JSON 查个股多日历史 |
| `/api/history/export.csv` | 从 JSON 导出 CSV |

### 相关函数（server.py）

`_history_json_dates` / `_history_json_day` / `_history_json_stock` / `_history_json_export`

## 5. 复盘进度条

复盘页点"收盘复盘"后，前端轮询 `/api/review/progress?date=` 显示抓取进度（涨停池→指数→红绿盘→三一票→连板题材→完成），避免长时间无反馈。

## 6. 早盘预案 Skill

`.claude/skills/daily-plan/SKILL.md` 承载预案生成方法论：

- 数据源接口清单、manual 字段归属表（agent填/留用户/前端回填）
- 预案骨架模板、话术库（炸板6原则/一进二/断板预期/容量弹性低吸/绿肥红瘦/利润垫）
- 合并规则（只补空缺）、数据口径警告（不写今日实况）

## 7. 竞价抓取数量（50 只）

后端竞价抓取只保留**竞价金额前 50** 只（腾讯/东财/akshare 三个数据源统一截断），减少每轮抓取与存储量。

- 常量：`AUCTION_TOP_N = 50`（server.py）
- 前端已移除"只看前60"开关（数据只 50 只，开关失去意义）
- 原"前 200"按竞价金额排序截断 → 前 50；竞价金额 51-200 的超高分股会被丢弃

## 8. 昨连板标注（位置过滤列）

竞价表格新增**"昨连板"列**，帮用户识别"高位追高"的高风险股（竞价第一 + 昨日高位连板 = 大面高发）。

### 数据来源

东财对历史涨停池只保留约一周，无法长期回查。方案：**每天收盘自己落盘当日涨停池**，次日竞价读取标注。

- 收盘任务（15:05）调 `save_ztpool_json(date)` → 当日涨停池连板明细写入 `data/ztpool/<日期>.json`（含每只涨停股的 code/name/industry/ztCount/lb 连板数）
- 次日竞价 `_build_snapshot` 调 `load_prev_lb_map()` → 读最近一个交易日涨停池，给竞价股补 `prevLb` 字段（昨 N 连板；0=昨日未涨停）
- **不依赖 MySQL**，纯本地 JSON

### 前端显示

- 表格"昨连板"列：`2板` 青色高亮（≥2 板高位）、`1板` 灰色、`—`（昨日未涨停）
- 排序可用（data-key=`prevLb`）

## 9. 情绪周期环境标签

竞价页 Top 区显示**当前市场情绪周期**环境标签 + 竞价第一晋级概率提示，用于规避"退潮期竞价第一易大面"。

### 存储

收盘任务（15:05）调 `save_sentiment_json(date)` → 情绪摘要写入 `data/sentiment/<日期>.json`：
涨停数 zt / 跌停数 dt / 炸板数 zb / 最高连板 maxTier。**不依赖 MySQL**。

### 周期判定

竞价页加载时 `_build_snapshot` 调 `classify_environment()`，读最近 8 日情绪序列判定（竞价在 9:25，当日情绪未定，故用最近交易日收盘摘要）：

| 条件 | 状态 | 前端色调 | 提示 |
|---|---|---|---|
| 涨停≥55 + 高板≥4 + 情绪升温 | 上升期 | 红（pos） | 适合竞价，晋级概率大 |
| 涨停降≥15% 或炸板≥20 或涨停≤40 | 退潮期 | 绿（neg） | 谨慎，高位追高易大面 |
| 连续≥2 天涨停≤25 | 冰点期 | 青（ice） | 冰点易产龙，低位启动可关注反转 |
| 其余 | 分歧期 | 橙（warn） | 看题材持续性 |

冰点识别"连续退潮后情绪反转产龙"的例外情形——退潮期的谨慎建议在冰点反转为关注机会。

### 前端显示

- 竞价页 Top10 上方环境标签条：`<状态>（涨停N家·炸板N家·...）+ 建议`
- 若竞价第一名是昨日连板股（prevLb≥2），额外提示"第一名是昨日连板股，追高需谨慎"

### 数据累积

情绪判定需多日数据。从启用起每天收盘任务自动落盘，几天后周期判断才准确；首日显示"暂无情绪数据"。

## 10. 赚钱环境预测页面

用户交易哲学：做股票最关键是看"赚钱环境"（当前哪种打法能赚钱），而非单纯大盘涨跌。分四类，通过每日收盘数据分析：

| 环境 | 看什么 |
|---|---|
| 趋势票赚钱 | 指数>MA20/60 + 红盘广度 + 头马数 + 题材广度 + 量能 |
| 短线赚钱 | 连板晋级率 + 隔日溢价 + 高度梯队 + 炸板健康 + 涨停规模 |
| 抱团赚钱 | 成交集中度(Top10/20占比) + 红绿背离 + 龙头高度 + 主线收敛 |
| 混乱/轮动 | 板块一日游(Jaccard) + 昨领涨消失 + 炸板高 + 追涨亏钱 |

页面：`http://<服务器IP>:8010/env.html`（各页顶栏"环境"进入）。

### 判定引擎

`backend/env_engine.py`（纯计算无网络）：`compute(signals, rules)` → 四类分数(0-100) + 结论。结论合成：最高分≥`activateFloor`(45) 为主结论；与第二差≤10 且第二≥35 → "主类+伴生类"；均未达标 → 防守。阈值集中在 `data/env_rules.json`（用户可改，改文件即生效）。

### 信号来源（六组，全部当日收盘可得）

| 组 | 信号 | 来源 |
|---|---|---|
| S1 涨停结构 | zt/zt_real/dt/zb/炸板率/连板分档/最高板 | sentiment JSON（本地） |
| S2 红绿量能 | 红绿盘/占比/两市量能/较昨 | market_daily JSON（新） |
| S3 晋级溢价 | 连板晋级率/首板2板率/昨涨停溢价/昨连板溢价 | D-1 ztpool + D ztpool + D收盘后腾讯批量涨幅 |
| S4 板块持续 | 今明领涨 Jaccard/昨领涨今涨停/覆盖行业数 | sentiment D/D-1（本地） |
| S5 成交集中 | 两市总额/Top10/20占比/涨跌中位 | 腾讯全市场快照（收盘一次） |
| S6 趋势主线 | 指数>MA20/60/MA20方向/头马数 | market_indices 累积 + 板块缓存 |

**隔日指标当天算**：晋级率/溢价用 D-1 本地涨停池 + D 收盘后一次腾讯批量涨幅得出——D 收盘全天定格，即"昨天打板今天赚不赚钱"的最终答案，不用等 D+1。

### 落盘文件

| 文件 | 内容 |
|---|---|
| `data/market_daily/<日期>.json` | 市场画像(红绿/中位数/量能/Top占比/指数) |
| `data/market_indices.json` | 4 指数收盘序列累积（供 MA20/60） |
| `data/env/<日期>.json` | 环境画像(signals/scores/conclusion/manual) |
| `data/env_rules.json` | 阈值（用户可改） |

### 接口

- `GET /api/env?date=YYYY-MM-DD[&refresh=1]`：环境画像（refresh 重算）
- `GET /api/env/dates`：有环境数据的日期列表
- `GET /api/env/history?days=12`：近 N 日环境序列（历史曲线）
- `POST /api/env {date, manual}`：人工覆盖结论（manual=null 清除）

### 调度

收盘 15:05 自动跑（`_run_close_review` 串行：复盘→涨停池→情绪摘要→市场画像→环境画像→预选票）。成本 ≈ 指数日K(4s) + 腾讯批量涨幅(<1s) + 全市场快照(已由复盘承担)。

### 数据累积

需多日数据。启用后每天收盘自动落盘，几天后环境切换曲线才成形。人工覆盖可修正机器判断（环境半主观）。
