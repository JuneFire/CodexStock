# 量化选股器

每天 9:25 集合竞价结束后，从腾讯行情抓取竞价金额排名前 200 的个股，结合昨日成交额与流通市值计算竞价超预期强度，输出 Top10。东方财富接口在当前网络下不可用时自动降级。

## 启动

```powershell
python backend/server.py
```

然后打开 <http://127.0.0.1:8010>。

启动后每个交易日 9:25-9:30 会自动抓取一次并保存；不需要自动抓取时运行 `python backend/server.py --no-auto`。

竞价金额与竞价换手只在交易日 9:25 竞价结束后、开盘前有效；手动抓取也限定在该窗口，其他时间会提示错误，避免把盘中累计成交额当成竞价数据。

页面顶部点击“抓取竞价数据”，服务端会完成：
1. 通过腾讯全市场快照抓取竞价成交额前 200（排除北交所）；
2. 逐只拉取最近日 K，取上一交易日成交额与换手率；
3. 计算竞价占昨日成交比例、竞价金额强度（竞价金额/流通市值，单位 bp）、竞价换手，并按 30/30/20/12/8 权重输出 0-100 超预期分；
4. 按分数排序生成 Top10，并保存到 `data/latest.json` 与 `data/history/<日期>.json`。

> 保存规则：只有交易日 9:25-9:30 竞价窗口内抓到的快照才会写入 `data/latest.json`、`data/history/<日期>.json` 和 MySQL 历史库。窗口外（盘中/盘后/周末）手动抓取的结果**仅返回页面预览、不落盘**，不会覆盖 9:25 抓到的有效竞价数据，避免把全天累计成交额当成竞价数据。自动抓取仅在交易日 9:25-9:30 触发。

> 收盘自动任务：每个交易日 15:05 自动（1）抓取当日竞价股的最终涨幅更新到 MySQL `auction_stock.close_pct`，（2）把当日全天成交额/换手/收盘存为次日 9:25 的"昨日基准"（`auction_stock.yesterday_*`），（3）生成并保存当天完整复盘（指数/涨停池/连板/头马黑马）到 `sentiment_review`。历史页表格与个股详情可查看"收盘涨幅"列，复盘页历史列表可查看每日自动生成的复盘。

> 竞价抓取提速：9:25 抓竞价时优先读上一交易日已存的"昨日基准"缓存（收盘时写入），命中则跳过逐只拉取日K——抓取从约 3 分钟降到 1 秒内；缓存缺失的股票才逐只实时拉取。

> 交易信号推送：每个交易日 9:30 自动把当日竞价 Top3 个股推送到微信（Server酱），供手动下单参考。配置 `config.json` 的 `serverchan.sendkey`（sct.ftqq.com 获取），或设环境变量 `SERVERCHAN_KEY`。未配置时自动跳过推送。

## 数据源与降级

腾讯行情为主，东方财富直连与 akshare 依次兜底：

| 数据类型 | 主源 | 兜底 1 | 兜底 2 |
|---|---|---|---|
| 全市场快照 | 腾讯 `stock_zh_a_spot_tx` | 东财 `push2` 直连 | akshare（东财/新浪） |
| 昨日成交额/换手/收盘 | 腾讯 `stock_zh_a_hist_tx` | 东财日 K 直连 | akshare 日线 |
| 实时指数 | 腾讯 `qt.gtimg.cn` | 东财直连 | akshare 新浪指数 |
| 板块字段 | 新浪行业板块映射 | 东财 `f100`（东财直连命中时） | 回退“其他” |

单位换算：腾讯快照成交额为万元（×1e4 转元）、市值为亿（×1e8 转元）、成交量单位为手；腾讯日 K 换手率为小数（×100 转 %）。

板块映射抓取自新浪行业板块（约 49 个），按“先到先得”归属（同一股票出现在多个行业时取第一个），缓存到 `data/sector_map.json`，每天最多重建一次；构建失败时保留旧缓存，未覆盖的股票板块显示“其他”。

快照不含北交所（4/8/9 开头）。原东财口径含北交所，本工具刻意排除，以匹配沪深竞价与涨停阈值（9.8%/19.5%）。

## 本地模式

不启动服务也可以直接双击 `index.html` 使用演示数据，或下载 CSV 模板后导入自己的竞价数据。演示数据仅用于界面与筛选逻辑预览，不代表真实行情。

## CSV 模板

点击顶栏“模板”下载，列包含：

`代码,名称,板块,竞价价,竞价涨幅,竞价金额(元),竞价量(手),竞价换手(%),量比,流通市值(元),昨日成交额(元),昨日占比(%),金额强度(bp),超预期分,状态`

导入时支持 UTF-8 与 GBK 编码；金额列带“万/亿”后缀也会自动换算为元。

## 说明

- 行情快照中的成交额在 9:25-9:30 抓取时代表集合竞价成交额，开盘后为全天累计值，因此建议每天 9:25 后立即抓取；非竞价窗口抓取的结果仅预览、不会保存，也不会覆盖 9:25 的有效竞价快照。
- 昨日成交额通过日 K 接口逐只获取，200 只约需 30-60 秒。
- 抓取失败时页面会提示，可先用“演示数据”或 CSV 导入继续使用。

## 历史竞价数据（MySQL）

行情接口不提供历史竞价数据，历史快照由本地逐日累积保存到 MySQL（每天保留最后一次有效竞价快照）。写入 MySQL 前会再次校验抓取时间必须在 9:25-9:30 竞价窗口内且与快照日期一致，防止 9:30 后拿到的累计数据污染历史库；9:30 后即使生成了 JSON 也不会写入 MySQL。数据库不可用时不影响抓取，页面会提示“MySQL 未连接”，原有 `data/history/日期.json` 存档仍然保留。

### 配置

1. 安装依赖：

```powershell
pip install -r requirements.txt
```

2. 复制 `config.example.json` 为 `config.json`，填写本地 MySQL 账号：

```json
{
  "mysql": {
    "host": "127.0.0.1",
    "port": 3306,
    "user": "root",
    "password": "你的密码",
    "database": "cn_stock_quant"
  }
}
```

也可以使用环境变量 `MYSQL_HOST`、`MYSQL_PORT`、`MYSQL_USER`、`MYSQL_PASSWORD`、`MYSQL_DB`。服务启动时会自动创建数据库和表（`auction_day`、`auction_stock`），完整建表语句见 `docs/schema.sql`。

3. 启动服务：

```powershell
python backend/server.py
```

打开 <http://127.0.0.1:8010>，顶栏“历史”按钮进入历史页面；每个交易日抓取成功后会自动写入 MySQL。

### 导入历史 JSON

`data/history/` 里已有的合法快照可以一次性导入：

```powershell
python backend/migrate_history.py
```

无效快照（例如抓取时间不在 9:25-9:30 竞价窗口内）会跳过并提示。

### 接口

- `GET /api/history/dates?page=1&page_size=30`：历史日期列表（分页）。返回 `{ok, dates, total, page, page_size, has_more}`；`dates` 按日期倒序，每页最多 `page_size` 条（默认 30），`total` 为总天数，`has_more` 表示是否还有下一页
- `GET /api/history/date?date=YYYY-MM-DD`：某日完整快照
- `GET /api/history/stock?code=600000`：个股多日历史
- `GET /api/history/export.csv?date=YYYY-MM-DD`：导出当日 CSV（UTF-8 BOM，Excel 可直接打开）

## 情绪周期复盘（Web 版）

> 对应 Excel《复盘预案》模板的网页版。顶栏“复盘”按钮进入。

页面按 Excel 模板分为 4 大板块：**指数复盘**（收盘点位/涨跌/成交量/红绿盘）、**情绪与竞价**（竞价 4 时间点表现、涨停/跌停/炸板/溢价统计、今日情绪→次日风标）、**题材与消息**、**个股连板梯队**（8板→1板→首板 + 当天最好机会）。

点击“收盘复盘”抓取当日数据（交易日 15:00 后），自动字段包括：

| 字段 | 来源 |
|---|---|
| 指数收盘/涨跌点数/涨跌幅度/成交量/今开 | 腾讯指数日K |
| 红盘/绿盘/平盘家数 | 腾讯全市场快照 |
| 涨停/跌停/炸板数、连板梯队、最大封单、前排题材、封单亿元以上 | 东财涨停池系列接口 |
| 昨涨停溢价 / 连板溢价 | 东财昨日涨停表现聚合 |

手动字段（竞价三一票、当天最好机会、重点消息、题材压力支撑、次日预案等）在页面直接编辑，“保存”后写入 MySQL `sentiment_review` 表。题材点位因概念板块接口不可用需手动填写。

**头等马 / 黑马**（复盘页左侧）：按新浪 49 行业板块等权合成指数，**头等马** = 站上 60 日线且 OBV 站上均线，**黑马** = 未站上 60 日线但 OBV 站上均线（弱转强），各显示最强 5 个板块（代码/名称/涨幅）。点“收盘复盘”时随复盘数据一并合成并写入 `sentiment_review.horses_json`。复盘页切换日期会加载对应日期的头马/黑马（该日未保存则回落当前缓存并标注“未保存”）。

接口：

- `GET /api/review?date=YYYY-MM-DD[&refresh=1]`：读取某日复盘；`refresh=1` 重新抓取并覆盖缓存（非交易日返回 400）
- `POST /api/review`：保存手动字段 `{date, manual}`
- `GET /api/review/horses[?date=YYYY-MM-DD]`：当前或指定日期的头马/黑马
